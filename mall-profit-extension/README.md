# 商店利润筛选器

这是一个适用于 Chrome / Edge 的 Manifest V3 扩展，同时支持两个商城：鸢尾花商城（`https://mall.vesego.xyz/`）和 SMCShop（`https://shop.whalemc.com/`）。打开任一站点后，页面右下角会出现“利润排行”按钮，点击即可使用。

当前版本：`v1.11.0`

## 功能

同一个扩展按当前站点自动切换能力：

- **鸢尾花商城**：单件利润 + 总利润 + 异常价格过滤 + 版本筛选 + 港口黑名单，功能完整。
- **SMCShop**：只做单件利润排行。它的数据是玩家客户端上报的商店挂单，服务端已经按物品聚合好
  「最低卖价 / 最高收价」，所以打开面板就有排行，没有「开始计算」这一步。它的明细接口一次最多
  返回 200 条而且是模糊匹配，依赖逐物品取明细的总利润 / 异常过滤 / 港口黑名单在这里算不准，
  扩展会把这些控件直接隐藏；数据里也没有版本标记，版本筛选同样不提供。

下面带「仅鸢尾花商城」的功能只在第一个站点出现。

- 读取商城公开报价接口，不抓取页面 DOM。
- **点击利润列表里的商品名称，会直接在商城页面中打开该物品的详情（物品报价 / 历史价格），不需要手动关闭面板再去搜索。详情会盖在利润排行面板之上，关掉详情后面板原样回来。**
- 单件利润 = `最高收购价 - 最低出售价`，只保留正利润商品。
- 支持最低在售数量筛选，只显示 sellAmount 不低于指定值的商品。
- （仅鸢尾花商城）支持按 vanillaId 筛选“原版 + 非原版”“仅原版”或“仅非原版”。
- （仅鸢尾花商城）支持港口黑名单：屏蔽指定港口后，重新计算价格、在售数量和总利润。
- （仅鸢尾花商城）港口黑名单支持 JSON 文件导出和 JSON/TXT/CSV 导入，并保存在扩展中。
- （仅鸢尾花商城）支持同商品异常报价过滤，可切换关闭、严格 5×、推荐 10× 和宽松 20×。
- （仅鸢尾花商城）异常过滤按同商品报价中位数判断，低于中位数 1/N 或高于中位数 N 倍的报价会被剔除；小样本报价使用最大相邻价差判断。
- 表格的每一列都能点击表头排序，升序降序随意切换，不再需要先用下拉选好排序方式。
- （仅鸢尾花商城）总利润会根据报价中的可交易数量，将最低出售报价与最高收购报价进行最优匹配。
- 忽略港口距离、传送和运输成本。
- （仅鸢尾花商城）默认使用 `includeTagged=false`，遵从商城对标记商店和失效商店的处理。
- 商品列表、总利润和异常过滤结果都会缓存 5 分钟。
- 开始计算、重新计算均需手动点击，不会在打开面板或切换筛选条件时自动启动。
- （仅鸢尾花商城）支持限定计算范围：默认算全部商品，也可以只算「当前筛选结果」（按搜索、最低在售数量、商品版本筛出来的那些，不再截断条数）。「开始计算 / 重新计算」按钮上会标出这一轮要算多少条。
- （仅鸢尾花商城）总利润计算显示进度，可随时停止。
- 报价抓取失败的商品会被单独记下来，状态栏提供“重试失败项”，只重新请求失败的那几个，已经算好的结果不受影响。
- 计算结果超过 5 分钟有效期后照常显示，并在状态栏说明已过期，不会突然从表格里消失。
- 搜索和最低在售数量输入带 220ms 防抖，连续敲字符时不会每敲一下就重排一次整张表。

## 安装

1. 打开 Chrome 的 `chrome://extensions/`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本目录：`mall-profit-extension`。
5. 打开或刷新 `https://mall.vesego.xyz/`。

## 使用说明

以下条目默认讲的是鸢尾花商城。**SMCShop 上只有这几条适用**：打开面板即出排行（没有“开始计算”）、搜索、点表头排序、最少商店数筛选、点商品名跳详情（面板会自动收起，重新点“利润排行”回到榜单）。

- 默认进入“单件利润”模式，使用推荐 10× 异常价格过滤。
- 打开面板只会读取商品列表；启用异常过滤或总利润模式后，需点击右上角“开始计算”。
- 计算范围默认是「全部商品」。切到「当前筛选结果」后，只有筛选结果里的商品会去请求报价，其余商品一个请求都不发；状态栏会常驻说明当前范围。
  - 想少算一点就先用搜索、最低在售数量或商品版本把范围收窄，按钮上的条数会跟着变。
  - 「重试失败项」不受计算范围限制，只补上一轮失败的那几个商品。
- 计算完成后会缓存结果，缓存 5 分钟内有效。关闭再打开会直接显示缓存，不会自动重新请求。
- 缓存过期后结果**仍然显示**，状态栏会提示“已超过 5 分钟有效期”，计算按钮同时变成“重新计算”，点一下即可刷新；不会出现表格突然变空的情况。
- 如果部分商品的报价没抓到（例如网络抖动），状态栏会出现“重试失败项（N）”。点它只会重新抓这几个商品，已经算好的结果不会重算；全部补齐后按钮自动消失。
- “刷新数据”只重新读取商品列表，不会自动启动报价计算。
- 异常过滤不会只隐藏某一个总价字段，而是从买卖报价、在售数量和总利润匹配中一起剔除异常报价。
- 异常过滤是统计规则，不代表报价一定无效；正常报价差异较大时可以切换到 20× 或关闭过滤。
- 点击“总利润”后，扩展会读取各商品的收购和出售报价并计算可执行的最大利润。由于商品较多，第一次计算可能需要约 1 至 2 分钟，具体取决于接口速度。
- “刷新数据”会清空缓存并重新读取。
- 搜索框只按商品名称过滤；输入带 220ms 防抖，停下来之后才会重排表格，输入框里的尾随空格会保留。
- 点击表头即可排序：点一次是「高 → 低」（商品列是名称升序），同一列再点一次反转；箭头指示当前方向，当前排序列的表头会加深。除「#」序号列外每一列都能点。
- 排序只重排当前表格，不会触发或打断报价计算，搜索、在售数量、商品版本等筛选条件都不受影响。
- 最低在售数量留空表示不限；输入数量后，当前表格和统计结果都会按该下限筛选。
- “商品版本”依据商城返回的 vanillaId 判断：有该字段为原版，否则为非原版。
- 点击商品名称即可跳到商城页面中该物品的详情：扩展会在商城的物品列表里定位该物品并打开它，被选中的那一行会短暂高亮，方便确认落点。
  - **详情会显示在利润排行面板之上**，面板既不关闭也不缩小，只是被详情盖住；关掉详情后就原样回到排行，之前算好的结果还在。
  - 跳转只使用商城自己的界面，不会改动商城的筛选条件（除非目标物品不在当前列表里，此时会自动在商城搜索框填入物品名并保留，便于你继续查看）。
  - 跳转不会触发或打断报价计算；如果计算正在进行，跳到详情后计算会在后台继续。
  - 只要当前页面能读到商城的物品列表即可跳转（`/`、`/mall` 都可以）；如果页面里完全没有商城物品列表，会在面板里给出提示而不会乱跳。
  - 商城详情开着时按 `Esc` 只会关掉它，不会连带把利润面板也关掉；详情关掉后再按 `Esc`，面板才关闭。
- 点击“港口黑名单”可选择、搜索或手动添加港口；导出会生成 JSON 文件，导入支持 JSON、TXT 和 CSV。
- 修改港口黑名单后需要手动点击“开始计算”，新的屏蔽条件才会应用到报价和总利润。
- 总利润不是“单件利润 × 在售数量”，而是按买卖报价数量配对后的利润，因此可能出现单件利润很高但总利润较低的商品。

## 文件结构

- `manifest.json`：Chrome 扩展配置。
- `content.js`：页面注入、界面、缓存与流程编排（两个站点共用）。
- `site-adapters.js`：各站点的接口地址、字段映射、能力开关、列名与跳转方式。
- `profit-core.js`：利润匹配、排序与港口黑名单解析算法。
- `content.css`：页面内嵌界面样式。
- `tests/profit-core.test.js`：核心算法测试。

## 更新说明

### v1.11.0

- 支持第二个商城 **SMCShop**（`shop.whalemc.com`）：同一个扩展按当前站点自动切换数据源、界面文案和能力。
- SMCShop 只做单件利润排行。该站的服务端已经按物品聚合好「最低卖价 / 最高收价」，一个请求就能拿到全库
  8700 多个物品，所以打开面板直接出榜单，没有「开始计算」这一步。
- SMCShop 上**隐藏**该站做不到的功能（总利润、异常价格过滤、版本筛选、港口黑名单、计算范围），
  而不是留一堆点了没反应的下拉。原因是它的明细接口一次最多返回 200 条且是模糊匹配
  （查「圆石」会被「深板岩圆石」占满名额），依赖逐物品取明细的计算在这里不准。
- 点商品名跳详情按站点分开处理：鸢尾花商城的详情是浮层，面板保持打开、由详情盖在上面；
  SMCShop 的详情是页面正文，面板会自动收起让位，重新点「利润排行」即可回来。
- 两个站点的缓存分开存放（SMCShop 的键带 `.smcshop` 后缀），不会互相读到对方的数据。

工程：

- 新增 `site-adapters.js`：把两个站点的接口路径、字段映射、能力开关、列名和跳转方式收敛成一份纯数据描述。
- `tools/e2e/jsdom-harness.js` 增加 9 条 SMCShop 断言（总数 81 → 90）。
- 新增 `tools/e2e/run-smcshop.js`：在真实站点上验证排行、隐藏的控件、跳转收起面板与精确匹配。

### v1.10.0

变更：

- 新增「计算范围」：默认仍是全部商品，也可以只算「当前筛选结果」。
  商城有 8000 多个商品、其中约 430 个是正利润，此前只要点一次计算就要为这 430 个商品各发两次报价请求；
  现在可以先用搜索 / 最低在售数量 / 商品版本把范围收窄，只算真正关心的那批，
  「开始计算 / 重新计算」按钮上会直接标出这一轮要算多少条。
- 新增「重试失败项（N）」按钮：报价抓取失败的商品不会写进缓存，按钮只会重新请求这些商品，
  已经算好的结果原样保留，全部补齐后按钮自动隐藏。它的范围固定在上一轮失败的那几个，不跟随「计算范围」。
- 缓存过期不再丢数据：结果超过 5 分钟有效期后继续显示（状态栏提示「已超过 5 分钟有效期」），
  计算按钮同时变成「重新计算」。此前过期结果会被直接从表格里剔除，表现为「算完过一会儿回来，
  排行凭空变空」，容易被当成数据坏了。重开页面时过期缓存也会照常载入。
- 搜索与最低在售数量输入加 220ms 防抖。此前每敲一个字符都会做一遍全表筛选 + 排序并重建整张表，
  现在是停下来之后只重排一次。
- 一次渲染里的「可见行」只计算一遍：摘要和表格此前各自调用一次 `getVisibleRows()`，也就是每次
  渲染要跑两轮全表 map + filter + sort。摘要里的「最高单件利润 / 最高总利润」也从「整表排序取第一行」
  改成一次扫描取最大值。
- 输入框只在内容确实不同、且用户没有正在编辑时才写回，不再吃掉搜索词末尾的空格、不再把光标顶到末尾。

工程：

- `tools/e2e/jsdom-harness.js` 增加 29 条断言（总数 52 → 81）：输入防抖（用 `sortRows` 调用次数当探针，
  一次渲染必须只出现 1 次）、一次渲染只算一遍可见行、过期缓存保留与状态栏提示、失败项重试只碰失败的
  那一个商品、计算范围跟着筛选条件收窄（用一张 12 个商品的长夹具，搜索「矿石1」把范围压到 3 条，
  再断言报价接口只碰了这 3 个）、最低在售数量在表格与计算范围里口径一致、换异常过滤倍数后
  旧的失败记录被清空。
- 新增 `tools/e2e/run-scope.js`：真实浏览器里把范围设成「当前筛选结果」，再用搜索把结果压到几个商品，
  点一次计算，统计报价接口到底碰了哪几个商品（实测只碰筛选结果里的那几个，而非 38 个正利润商品）。
- 新增 `tools/e2e/run-perf.js`：真实浏览器里数 `#mpe-tbody` 的重建次数来验证防抖，并测量一次完整重排的耗时。
- `tools/e2e/gen-inject.py` 把未被改写的原生 `fetch` 暴露为 `window.__mpeOriginalFetch`，让驱动可以
  退回真实商品目录规模（默认会被改写成单页，免得每次等 82 页）。

### v1.9.0

变更：

- 排序从工具栏的下拉框改成**直接点表头**，跟普通表格一样升序降序随意切换。
